# inc4-retail-pos

## Причина
Из-за перебоев с электроэнергией произошел сбой часов в кассового терминала.

## Доказательство
1. В файле **pos_sync.log** видно, что дата записи *POS-02 boot: RTC battery low, system time not synchronized (ntp: no server configured)* датируется 2026-01-01 00:00:07, хотя предыдущая запись датировалась 2026-10-20 21:05:20
2. В фале **exchange_retail.log** есть сообщение <span style="color:yellow">retail.WARNING: shop=2 shift=1188: 143 receipts skipped: document date 01.01.2026 is before 1C closed-period boundary 01.10.2026</span>, сообщающая о дате документа 01.01.2026, и что данная дата находиться перед границей закрытого периода 1С 01.10.2026

## Что сделать сейчас
1. Сделать коррекцию данных для 1С: либо для смены **1188** поменять дату в отправляемых данных и сделать повторную синхронизацию, либо обратиться к ответственному специалисту для ручного добавления данных в 1С
2. Установить корректное время на кассовом терминале

### Проверка
Убедиться через **exchange_retail.log**, что документ о розничных продажах создан за 21.10.2026 для магазина №2. Так же нужно сделать проверку, что выручка появилась в 1С

## Как не допустить повторения:
1. Добавить в модуле обмена валидацию дат в выгружаемых чеках, в случае ошибки блокировать открытие смены и отправлять сообщение ответственному лицу. Также добавить мониторинг пропущенных чеков
2. Настроить NTP-севрер на всех кассах для автоматической коррекции времени при загрузке


## Ответ сотруднику
Из-за утреннего отключения света на кассе сбилось системное время, поэтому вчерашние чеки ошибочно записались с датой из прошлого и заблокировались защитой от изменения закрытого периода в 1С. Мы уже устраняем причину сбоя часов и перенесем продажи в базу данных в ближайшее время.
