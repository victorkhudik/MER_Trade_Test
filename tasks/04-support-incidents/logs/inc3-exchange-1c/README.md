# inc3-exchange-1c

## Причина
Был создан новый клиент **K-117** c unp **190000000**, но не создан на 1С. Его заказ выдает ошибку при отправке на 1С: <span style="color:red">1C HTTP 422: {"error":"Контрагент не найден","unp":"190000000","client":"K-117"}</span>. И модуль обмена, при получении ошибки, прекращает отправку заказов.

## Доказательство
1. В файле **queue_snapshot.txt** видно, что клиент с unp **190000000** был создан в 2026-10-22 07:51:10, первые его заказ был создан в 2026-10-22 07:57:40 с id **88414**
2. В файле **exchange.log** видно, что с 2026-10-22 07:58:03 по 2026-10-22 11:07:01 при отправке заказа **88414** выдается ошибка и останавливается процесс, так как количество заказов в статусе pending растет.

## Что сделать сейчас
Добавить контрагента **K-117** с unp **190000000** в 1С или сделать синхронизации с 1С списка клиентов.

### Проверка
Убедиться через exchange.log, что после добавления контрагента заказ с id **88414** успешно отправлен и есть сообщение <span style="color:green"> exchange.INFO: job #88414 ORD-B2B-7781 -> 1C OK</span>

## Как не допустить повторения:
1. Изменить логику модуля обмена, чтобы, при получении ошибки после отправки одного заказа в 1С, другие заказы продолжали отправляться. Заказам, которые не получилось отправить после нескольких попыток, менять статус с pending на pending_failed и автоматически отправлять сообщение ответственным лицам
2. Сделать синхронизацию с 1С при изменении списка клиентов


## Ответ сотруднику
Утром в систему поступил заказ от нового клиента, которого нет в базе 1С, из-за чего автоматическая отправка заказов временно остановилось. Мы уже передали информацию для создания контрагента, после этого все накопившиеся заказы автоматически выгрузятся в 1С.
