# Модуль сопоставления заказов маркетплейса с выгрузкой 1С (Задание 01)

Данный проект представляет собой CLI-инструмент на **PHP 8.1+** для предварительной валидации и сверки заказов, поступающих из API маркетплейса (`orders.json`), со справочником номенклатуры и складских остатков 1С (`nomenclature_1c.csv`).

Модуль гарантирует, что в учетную систему 1С не попадут некорректные, отмененные или дублирующие заказы, а также заранее выявляет расхождения по ценам и дефицит остатков.

---

## Архитектура проекта

Код организован с использованием пространств имен (Namespaces) и PSR-4 автозагрузки:

```text
/
├── OneCNomenclatures/
│   └── OneCNomenclatures.php  # Загрузка и парсинг номенклатуры 1С из CSV
├── Orders/
│   └── ApiOrders.php          # Получение и декодирование заказов из JSON
├── data/
│   ├── nomenclature_1c.csv    # Выгрузка номенклатуры и остатков из 1С
│   └── orders.json            # Ответ API маркетплейса со списком заказов
├── vendor/                    # Зависимости и Composer Autoloader
├── OrdersCheck.php            # Главный исполняемый CLI-скрипт (точка входа)
└── README.md                  # Документация модуля
```

## Реализованная бизнес-логика

1. **Нормализация данных:**
   - **Артикулы (SKU):** Приводятся к верхнему регистру и очищаются от случайных пробелов (`normalizeSku`).
   - **Числа 1С:** Цены и остатки из CSV нормализуются с учётом специфического формата 1С (очистка от неразрывных пробелов `\xc2\xa0` и замена запятых на стандартную точку для `float`).
2. **Обработка статусов и дубликатов:**
   - **Отмененные заказы:** Заказы со статусом `cancelled` автоматически пропускаются.
   - **Дубликаты:** Заказы с повторяющимися идентификаторами (`id`) детектируются и отсеиваются с записью в лог ошибок.
3. **Валидация структуры и целостности:**
   - Проверяется наличие позиций в заказе (`items`), корректность итоговой суммы (`total`) и наличие цены у каждого товара. При обнаружении битых записей скрипт не падает, а фиксирует ошибку в логе.
4. **Сверка со справочником 1С:**
   - **Наличие SKU:** Проверяется существование артикула в базе 1С.
   - **Соответствие цен:** Сравнивается цена в заказе маркетплейса и учетная цена в 1С с погрешностью до `0.001`.
   - **Контроль остатков (включая совокупный спрос):** Выполняется проверка наличия достаточного количества товара на складе как для отдельного заказа, так и с учетом общего спроса (`skuDemand`) по всем активным заказам.

## Требования

- **PHP** версии 8.1 или выше
- **Composer** (для управления автозагрузкой PSR-4)

---

## Инструкция по установке и запуск

1. Убедитесь, что в корне вашего проекта настроен файл `composer.json` с поддержкой пространств имен `OneCNomenclatures\` и `Orders\`. Обновите автозагрузчик:
   ```bash
   composer dump-autoload
   ```

2. Убедитесь, что файлы данных (`orders.json` и `nomenclature_1c.csv`) находятся в папке `data/`.

3. Запустите скрипт проверки через терминал (CLI):
   ```bash
   php OrdersCheck.php
   ```

## Формат вывода отчета

Скрипт формирует в консоли наглядную таблицу со статусом обработки каждого заказа:
- **`ГОТОВ К ВЫГРУЗКЕ`** — заказ успешно прошел все проверки (цены, остатки, структуру).
- **`ОШИБКА СОПОСТАВЛЕНИЯ`** — обнаружены расхождения по ценам, дефицит остатков или отсутствие артикула в 1С.
- **`ПРОПУЩЕН`** — отмененные покупателем заказы или дубликаты.
- **`ОШИБКА ДАННЫХ`** — критические дефекты структуры заказа (например, пустой список товаров).

В нижней части консоли выводится подробный **Лог ошибок и предупреждений** для оперативной работы менеджера или технической поддержки.
